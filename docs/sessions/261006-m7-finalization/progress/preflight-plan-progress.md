## 2026-10-06 阶段二：纠正推理错误（dlg-20261006-025815-70f6c7）

只改原两个文件，未跑测试/服务，未改运行代码，未扩调查。本段纠正阶段一正文里的以下结论，
**阶段一原文按历史原保**（见文首阅读须知）：

- **纠正 1（503 对 503）**：计数相等**只**证明计数相等。无同次 JUnit / node multiset 对照，
  用例集合是否相同为 **unknown**。作废阶段一的「同一份用例集合」与隐含的「排除用例差异」。
- **纠正 2（O_BINARY）**：具名用例 passed **只**证明那一个用例通过，**不**证明该改动没有在别处
  导致 55/24 中的任何失败。作废阶段一把 `O_BINARY` 具名用例 passed 当作排除该改动的证据。
  Linux 平台事实有 PR82 文档来源，保留；根因仍 **unknown**。
- **纠正 3（ps/负载）**：ps/负载/systemd 是**本卡执行当时观测**，两次红在 2026-10-05，相隔约
  一天，**不作因果输入**。作废阶段一「把 55/24 定性为运行环境差异」与以负载水位作判据的写法；
  一次安静环境下转绿**不能**证明负载相关。改为要求环境/版本/源码对照。
- **纠正 4（最小验证覆盖面）**：原方案只跑 cleanup 4 条，会漏掉 45+24 的 EOF 簇。改为至少覆盖
  cleanup 与真实 EOF 失败族**各一个原具名 case**（EOF case 从原 JUnit 取，不猜），同入口、
  base/head 环境与 child 退出签名。**全量本地漏斗仍是正常交付要求**，不豁免、不自授豁免、
  不把未知红当噪音。作废阶段一「只定向跑 `naked-shell` 参数集」的单簇写法。
- **纠正 5（macOS 与共享脚本）**：仓内查不到 ≠ 不存在，改记「本次读取范围未定位到」，由主脑从
  仓专属 memory / 前序链核实已有入口。作废阶段一「仓内无任何收据」的断言。六个共享未跟踪脚本
  归属本卡**未核实**，不得断言属主脑所有。
- **纠正 6（CPU/RSS 与格式覆盖）**：CPU/RSS 原 M7 已要求资源证据，**默认沿用工具外监控**，
  删该用户裁决点、不扩工具。作废阶段一把 CPU/RSS 列为待裁决项的写法。WAV/MP4 四次只是已知
  部分，补列 MP3/AAC/M4A/Opus 覆盖，缺样本记缺口、不缩完成条件。
- **纠正 7（AST 框架与 E 的依赖）**：AST 哈希框架**不需要**，改用 git 精确 blob
  （`git rev-parse <SHA>:<path>`）。卡 E 改为「静态准备可并行，**运行验收必须依赖它实际测试的
  runtime SHA**」，不得声称完全不依赖 `MERGED_SHA`。

  用户裁决取代。
